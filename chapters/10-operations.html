第 10 章 · 让世界看到你

上线之后

域名能访问只是开始。这一章讲怎么知道有多少人来过、他们关心什么、怎么让搜索引擎找到你、怎么持续迭代而不变成一个"曾经上线过但已经被遗忘"的项目。

本章学完后你会拥有 一套上线后的最小运营流程:看访问、补 SEO、收反馈、每周小迭代,以及判断这个项目还值不值得继续做。

10.1 加访问统计

上线后第一件事不是疯狂改页面,而是知道有没有人来过。

访问统计不用一上来搞很复杂。你只需要知道:

  • 每天大概多少人访问。
  • 他们从哪里来。
  • 最常看哪些页面。
  • 手机和电脑比例如何。

工具可以选 Plausible、Umami、Vercel Analytics 或你熟悉的其他服务。Google Analytics 也能用,但对新手来说配置和隐私提示会复杂一些。

选择统计工具
请根据当前网站情况,给我 3 个访问统计方案。要求: 1. 新手能配置 2. 免费或低成本起步 3. 尽量少影响隐私合规 4. 说明每个方案需要往 index.html 加什么代码 先不要直接修改文件。
统计脚本涉及第三方服务,先选方案再加代码。

10.2 让 Google 知道你存在

搜索引擎不会立刻知道你的网站。你需要给它一点提示。

最小步骤是:

  1. 注册 Google Search Console。
  2. 验证你的域名或网站所有权。
  3. 准备 sitemap.xml,告诉搜索引擎有哪些页面。
  4. 准备 robots.txt,告诉搜索引擎哪些可以抓。

如果你的网站现在只有一页,也可以先做最简单版本。重点是让搜索引擎知道它存在。

生成 sitemap 和 robots
请根据当前静态网站结构,生成最小可用的 sitemap.xml 和 robots.txt。假设正式域名是 [填你的域名]。生成前先列出会包含哪些页面。
域名要换成你自己的正式域名,不要照抄占位符。

10.3 SEO 的最小集

SEO 听起来很玄,但新手先做最小集就够:

  • <title>:搜索结果里最醒目的标题。
  • <meta name="description">:一句话说明页面内容。
  • Open Graph 标签:别人把链接发到社交软件时,显示标题、描述和图片。
  • 清晰的 H1 / H2:让页面结构像一篇有标题层级的文章。
SEO 最小检查
请检查当前网站的 SEO 最小集: 1. 每页 title 是否清楚 2. meta description 是否存在且不重复 3. H1 是否唯一 4. 是否需要 og:title / og:description / og:image 5. 图片 alt 是否合理 先输出检查表,我确认后再补齐。
SEO 优先做“能被正确理解”,不要一开始追求复杂技巧。

10.4 持续迭代的流程

上线之后,最容易犯的错是两种:要么不再管它,要么每天乱改。

更稳的方式是每周一次小迭代:

看数据

看一眼访问量、来源、停留时间、用户反馈。

选一个问题

不要同时改十个点。选最影响转化或理解的一处。

让 Codex 小改

只改一个区块、一个文案、一个按钮或一个表单。

提交并部署

确认效果,做 Git 提交,推送后让 Vercel 自动部署。

长期来看,一个能坚持每周小改的网站,比一次性大改后再也不管的网站更有生命力。

10.5 收集反馈

早期项目最值钱的不是访问量,而是真人反馈。

你可以用三种低成本方式收集:

  • 页面底部加反馈按钮:跳到 Tally、Typeform 或邮箱。
  • 发给 5 个目标用户:不要只发给会夸你的朋友。
  • 问三个固定问题:看懂了吗?哪里想点?哪里不信?
加反馈入口
请给当前网站底部加一个轻量反馈入口。先给我 3 个方案:mailto 邮箱、Tally 表单、Typeform 表单。说明各自优缺点和需要改哪些 HTML。先不要动手。
纯静态站先用外部表单,不用急着搭后端。

10.6 何时该停下来

不是每个项目都值得一直做。停下来不是失败,有时是节省时间。

你可以用这张清单判断:

  • 有没有真实用户愿意试?
  • 有没有人愿意留下联系方式?
  • 你自己还愿不愿意每周投入时间?
  • 这个问题是不是别人真的痛?
  • 你改了几轮后,关键数据有没有变好?

如果连续几周没人反馈、你自己也没兴趣,可以把它当练习项目归档。你已经获得了最重要的东西:一套从想法到上线的经验。

动手试试
给你的网站做一次上线后体检
  1. 检查 title、description、H1。
  2. 确认是否有反馈入口。
  3. 列出本周最值得改的一处。
  4. 让 Codex 只改这一处并提交。
完成标志:你有一份上线后检查清单,并完成了一次小迭代。
你已经会了 给网站加最小统计和 SEO,收集真实反馈,每周做一次小迭代,并判断项目是否值得继续投入。
