App 第 00 章 · 桌面端入门

先看懂 Codex 桌面端

如果你没有编程基础,我更建议你先从桌面端 App 开始。它不像终端那样黑乎乎一片,你能看到项目、对话、改动、预览和结果。简单说:Codex App 就是一个让你用普通话安排 AI 干活的工作台。

内容依据
本套 App 教程按 2026 年 6 月 23 日核对的 OpenAI Codex 官方文档整理。按钮名字和入口可能更新,但核心概念:项目、线程、模式、审查、权限,会比较稳定。

它到底是什么

把 Codex App 想成一个“项目管家”。你把一个文件夹交给它,然后用人话说:

  • “帮我看看这个网站哪里不对。”
  • “把首页文案改得更像给小白看的。”
  • “打开预览页,看看手机端按钮有没有挤在一起。”
  • “每天上午帮我检查一次有没有新的报错。”

它不是只会聊天。它可以读文件、改文件、跑命令、看网页预览、留下改动记录,还可以在你允许的范围内操作浏览器或桌面 App。

新版桌面端还把很多“看得见的工作”放进来了:网页标注、Appshots、图片生成、非代码文件预览、自动化、技能、网页搜索、Git 审查和 Worktree 隔离。你不用一口气全会,先知道它们分别解决什么问题。

打开后先看哪几块

第一次打开 App,别急着找所有按钮。先按这四块看:

区域你要盯什么小白怎么理解
项目列表当前 Codex 正在哪个文件夹里工作确认“它在哪个房间干活”。
线程对话你说了什么、Codex 回了什么、任务是否还在跑这是你和它的工作记录。
Review / Diff新增了什么、删除了什么、哪些文件变了这是验收区,别跳过。
终端 / 浏览器 / 预览命令输出、网页效果、报错信息这是证据区,少猜多看。

你可以把 App 当作一个“可视化驾驶舱”:左边定范围,中间下指令,右边看改动,底部看运行结果。只要这四块关系清楚,界面再复杂也不会慌。

App 和 CLI 怎么选

你现在的状态建议先用原因
完全没写过代码Codex 桌面端 App能看见界面、改动和预览,心理负担小。
愿意学一点终端CLI 教程更轻、更直接,适合理解底层流程。
已经有一个项目文件夹App 或 CLI 都行App 更适合图形化审查,CLI 更适合熟练用户。
想让 Codex 同时跑几个任务App线程、Worktree、自动化这些能力更直观。

你会在 App 里遇到哪些功能

项目和线程

项目就是一个文件夹,线程就是一次对话。一个项目里可以有很多线程。

Local / Worktree / Cloud

Local 直接改当前项目;Worktree 隔离试验;Cloud 在远程环境跑。

Review 面板

看 Codex 改了哪些文件,给某一行留评论,再决定暂存、撤回或提交。

内置终端

不用离开 App,就能启动预览、跑测试、看错误输出。

内置浏览器

打开本地网页,直接在页面上圈出问题,让 Codex 按评论修改。

Computer Use

在你允许后,让 Codex 看见并操作桌面应用,适合 GUI 测试和复现问题。

自动化

让 Codex 定时检查、提醒、跑报告,有结果就放进你的待处理区。

技能、插件和 MCP

技能是固定套路,插件是打包安装,MCP 是连接外部工具的方式。

网页搜索

需要查最新官方资料时,可以让 Codex 搜索网页并附来源,别只靠记忆。

图片和文件

可以生成图片资产,也能预览或创建 PDF、表格、文档、演示文稿等文件。

最新功能先用人话记

截至 2026 年 6 月 23 日,桌面端 App 里最容易被新手忽略的能力,可以先这样理解:

功能一句话理解你该怎么开口
Worktree给 Codex 一份隔离副本,让它大胆试“请用 Worktree 试一个新版,先别影响当前文件。”
线程自动化让同一条对话过一会儿自己醒来继续检查“每 10 分钟看看部署是否完成,有结果再提醒我。”
内置浏览器评论在网页上直接圈问题,比口头描述更准“请处理我刚在浏览器里留的评论。”
Computer Use让 Codex 在你允许后操作桌面软件“只复现这个按钮流程,不要点账号和付款相关内容。”
Appshots把当前窗口发给 Codex 当上下文“我刚发了 appshot,先描述你看到了什么。”
Skills把固定流程变成可重复调用的做法“请用适合的技能处理,先说明会按哪些步骤来。”
Memories记住长期偏好,但不放秘密“请记住我喜欢口语化说明,不要记账号或密钥。”

如果你一时分不清,就把场景说清楚,让 Codex 帮你选:“这个任务更适合 Local、Worktree、Browser 还是 Computer Use?请先解释原因,再行动。”

第一周先别碰太多

Codex App 功能很多,但新手第一周只要练熟三件事:

  1. 让它先解释项目。任何项目先问“这里有什么文件,各自做什么”。
  2. 让它小步修改。一次只改一个区块、一个页面、一个问题。
  3. 每次看 Diff。看不懂就让它用人话解释,不要直接全盘接受。

自动化、MCP、Chrome、Computer Use、图片生成这些很强,但可以后面再用。你先把“打开项目 → 发指令 → 看改动 → 验收”这条主线跑顺。

这套 App 教程怎么读

如果你是零基础,按 A0 到 A6 顺序读。每章只记一个核心动作:

  1. A1: 把 App 装好,打开一个项目,发出第一句话。
  2. A2: 分清项目、线程和三种模式。
  3. A3: 学会看改动,别盲目接受。
  4. A4: 用浏览器、Appshots 和桌面操作处理“我看见了,但说不清”的问题。
  5. A5: 把重复工作交给自动化、技能、网页搜索和外部工具。
  6. A6: 调设置、记快捷键、管理记忆和守住安全边界。
第一句可以这么说
我是零编程基础用户。请先帮我熟悉这个项目:用通俗的话说明它是什么、有哪些文件、我应该先看哪里。先不要改文件。
第一次不要急着让 Codex 开改。先让它“带你逛一圈”,你会更有安全感。
动手试试
用四块区域复述一次 App 界面
  1. 打开 Codex App 和一个项目。
  2. 指出项目列表、线程对话、Review 面板、终端/浏览器分别在哪里。
  3. 问 Codex:“请告诉我你当前能看到哪个项目路径。”
  4. 确认它回答的路径就是你想让它工作的文件夹。
完成标志:你能用自己的话说清楚 Codex 现在在哪里工作、你在哪里看改动。
这一章先记住 Codex App 不是“聊天窗口”,而是项目工作台。你负责定范围、说目标、看结果;Codex 负责读文件、改文件、跑检查,并在需要越界时问你。
