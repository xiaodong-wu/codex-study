App 第 11 章 · 更新核对至 2026-09-10

2026 年 9 月功能更新

这次最大的变化叫 GPT-6 Astra。它更适合把代码、网页、资料和办公文件串成一件复杂任务。Codex CLI 也更新到 0.154.0,加入实验性 Worktree、运行中提问、插件即时刷新和一批安全修复。下面不背版本流水账,只讲这些变化会怎样影响你。

为什么你的界面可能不一样
本页依据 OpenAI 官方 What's new、Models 和 Changelog,核对到 2026 年 9 月 10 日。Astra 和部分新入口会分批开放,还会受套餐、地区、系统和工作区管理员设置影响。没有看到某个按钮时,先更新应用并检查账号可用范围,不必反复重装。

GPT-6 Astra:复杂任务优先考虑它

Astra 是目前官方推荐列表里能力最强的模型,重点不是“聊天更会说”,而是更会处理跨步骤、跨工具的复杂工作。比如先查资料,再操作网页,接着修改项目,最后交付符合模板的文档、表格或演示稿。

模型用人话说适合什么
Astra最强主力,判断更稳,也擅长电脑操作复杂开发、跨 App 工作、深度研究、重要交付物。
5.6 SolGPT-5.6 里的高能力型号复杂编码、Computer Use、研究和安全工作。
5.6 Terra日常能力和消耗更平衡一般开发、内容整理、常规工具调用。
5.6 Luna更快、更省规则清楚的提取、分类、格式转换和批量任务。

桌面端或 ChatGPT Work 网页版里,从输入框下面的模型选择器找 Astra。CLI 里可以明确指定:

terminal 
codex -m gpt-6-astra

别把“最强”理解成“每次都该用”。简单改字、批量整理和格式转换继续用 Terra 或 Luna 更划算。Astra 的 Fast tier 标注为约 2 倍速度,同时会增加额度消耗;开始大任务前先看看自己的用量。

CLI 0.154.0:这次哪些功能真有用

截至 9 月 10 日,官方更新记录中的最新版本是 Codex CLI 0.154.0。npm 用户可以这样升级:

terminal 
npm install -g @openai/codex@0.154.0
codex --version
新变化怎么用对你有什么帮助
Astra 进入模型列表输入 /model,或启动时加 -m gpt-6-astra。不用手动猜模型名,可以直接从列表选择。
实验性 Worktree启动时使用 --worktree,或在 TUI 里输入 /worktree。给新任务或分叉任务建隔离副本,减少互相改乱文件。
运行中提问Codex 工作时出现问题卡片,可选建议答案或填写自己的回答。回答问题时不会挤掉你正在写的下一条消息。
复制更完整/copy 可以复制状态输出或单项会话信息。粘贴到富文本编辑器时更容易保留格式。
Windows 后台服务多个会话可共用后台 Codex server。Windows 上的会话管理和更新更稳定。
Vim 编辑增强新增 R 替换模式,并改进撤销、重做和 Escape。只对已经习惯 Vim 键位的人有用,新手可以跳过。

Worktree 到底解决什么问题

Worktree 可以理解成“同一个 Git 项目的另一张工作桌”。主项目继续保持原样,新任务在隔离目录里改文件。你想同时试两个设计方案,或者让两条任务并行工作时,它会比大家挤在同一个文件夹里稳得多。

  1. 确认项目已经是 Git 仓库,并先保存重要的未提交改动。
  2. 用 codex --worktree 启动隔离会话,或在当前 TUI 输入 /worktree。
  3. 让 Codex 说明新 Worktree 从哪个分支开始、实际目录在哪里。
  4. 完成后先看 Diff 和测试结果,再决定合并、保留还是删除。
CLI 里的这套 Worktree 仍是实验功能
实验功能可能改入口、参数或行为。第一次先拿不重要的测试仓库练习,别把唯一一份未提交工作当试验品。桌面端已经有更直观的 Worktree 流程,零基础用户优先从 App 学。

插件和 MCP:少重启,登录失败更说得清

0.154.0 会让已经打开的会话发现新安装的插件工具,外部升级或回退插件后,也会刷新 Skills 和 Hooks。也就是说,新版 CLI 通常不必为了一个新插件整条会话重开;如果入口仍没出现,再检查版本、插件状态和工作区策略。

MCP 的 OAuth 刷新也更稳了。刷新失败时会明确显示登录挑战,让你重新授权;被拒绝的工具调用不会悄悄自动再跑一遍。看到登录提示时,完成授权后要自己确认是否重新提交刚才的操作。

另外,旧的 codex mcp-server 入口在 0.154.0 已经移除。普通用户连接外部工具仍用 codex mcp;开发者把 Codex 嵌进其他程序时使用 Codex App Server。

几项看不见,但很重要的安全修复

  • 工作区还没有被信任前,启动过程不会运行由工作区控制的辅助程序。
  • macOS 沙盒加强了对终端输入注入的阻挡。
  • 恢复或分叉远程任务时,会保留已经保存的权限设置。
  • 新会话和分叉会话会尊重服务器默认模型,除非你明确覆盖。
  • 同一条对话正在另一个 App 里写入时,恢复会先显示只读记录和重试入口,保护你还没发送的草稿。

这些变化不需要你打开某个开关,但能减少“还没确认就运行”“恢复后权限突然变了”这类风险。升级 CLI 的价值不只是拿新功能,也包括带上这些修复。

手机 Remote 也更像真正的任务面板了

9 月 8 日的 iOS 更新补强了远程协作:输入框里可以用 @ 提及其他任务;Codex 运行时提出问题,你可以直接回答而不丢草稿;文件浏览加入返回、最近文件和阅读位置记忆;新 Worktree 可以选择起始分支,也可以带上电脑当前的本地改动。

Voice 现在会尊重你选中的模型和推理强度,代码审查、断线重连和 Queue / Steer 切换也更可靠。手机仍然只是遥控器,任务真正运行在已连接的电脑上;涉及大段 Diff、账号操作和高风险审批时,回到电脑处理更稳妥。

升级后做一次 6 分钟检查

动手试试
确认新功能真的在你的账号上可用
  1. 运行 codex --version,确认 CLI 已到 0.154.0。
  2. 打开 /model,看看 Astra 是否已经出现在你的模型列表。
  3. 在测试仓库尝试 /worktree,只让 Codex 说明新目录,先不改文件。
  4. 安装或更新一个可信插件,观察当前会话是否自动出现新工具。
  5. 打开手机 Remote,检查任务提及、问题回答和文件返回是否可用。
  6. 最后用 /status 和 /diff 确认模型、权限、目录和改动都符合预期。
完成标志:你能说清楚 Astra、实验性 Worktree 和插件刷新是否已在自己的账号与设备上生效。
升级后第一次任务
请先只读检查当前环境,告诉我 Codex 版本、当前模型、推理强度、权限模式、工作目录、是否处于 Worktree,以及已经加载的插件和 MCP 工具。先不要修改文件或调用写入型工具。
先让它报环境,再开始真正任务,最容易发现“我以为已经升级,其实还没生效”的问题。
